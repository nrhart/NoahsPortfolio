Squirrel Life is my first solo game project applying the knowledge developed through my master’s program to a complete Unreal Engine game. I’m building it around scalable gameplay systems, maintainable architecture, and a documented workflow that connects design intent with engineering implementation.

I’m developing the core gameplay systems in C++, applying the four pillars of object-oriented programming: encapsulation, abstraction, inheritance, and polymorphism. These principles guide how I organize system responsibilities, define clear interfaces, reuse shared functionality, and support specialized behaviors as the game grows. The minigame framework puts inheritance into practice: shared functionality lives in reusable base classes, while individual minigames extend those classes with their own rules and behaviors. This lets me build new minigames on a consistent foundation without duplicating common logic, while Data Assets expose their configuration for designer-friendly iteration in the editor. Programming design patterns further support modular systems and designer-friendly iteration. Unreal Data Assets let designers customize minigames directly in the editor without changing core gameplay code. Object pooling allows obstacles to be spawned and reused, reducing repeated actor creation and destruction, while profiling tools help me monitor runtime performance, identify bottlenecks, and guide optimization decisions.

Although developed independently, the project is structured with future collaboration in mind. Clear system boundaries, documented technical decisions, and implementation guides are intended to help another developer understand the codebase, contribute confidently, and extend the game as its scope grows.

Implemented Systems

  • Reusable minigame framework: A shared C++ GameMode handles session flow, rewards, HUD setup, results, retries, and returning to the park. Running and climbing modes inherit this foundation and specialize their behavior, providing a starting point for future minigames.
  • Designer-friendly tuning: Unreal Data Assets expose per-stat and per-minigame values, including level caps, progression thresholds, reward rates, base speed, and speed scaling. Designers can adjust these values in the editor without changing the underlying C++ systems.
  • Shared stat progression: A reusable progression structure tracks levels and progress points for energy, running, climbing, flying, and swimming. Minigames award progress to their designated stat, with configurable thresholds and level caps; flying and swimming already have stat entries for future expansion.
  • Persistent progress: A central GameInstance maintains coins and stats across level changes, with SaveGame support for loading and saving progress. It also preserves the squirrel’s park position when moving between the park and minigames.
  • UI events: Delegates communicate live distance and speed, completed minigame results, and changes to coins and stats, allowing UI widgets to respond to gameplay updates.
  • Obstacle pooling: The runner spawner reuses obstacle actors and recycles them once they fall behind the player. Inactive pooled obstacles disable ticking and collision, reducing repeated actor creation and destruction.

A Dark Souls–inspired arena project focused on demonstrating design patterns in UE5. The Type Object pattern drives enemy behavior — each enemy archetype is built from composable data assets rather than hardcoded logic. A custom C++ Behavior Tree controls AI decision-making, and the Player State pattern manages persistent player data across the encounter. The arena environment draws from Souls-like level design principles: tight geometry, deliberate encounter pacing, and environmental storytelling.
